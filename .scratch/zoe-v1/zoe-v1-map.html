Resolved 5

  • 05

    Research: compliance for scheduling data (HIPAA, SOC 2, BAAs)

    Resolved
    • A staff work schedule is not PHI: HIPAA excludes employment records held by a covered entity as employer (45 CFR 160.103). Shifts, rosters, time off, punches and payroll stay out of scope unless they carry patient data.
    • A BAA is needed only if Zoe touches patient PHI. Hospitals may ask for one anyway; keep a template.
    • SOC 2 Type II is the procurement norm for scheduling vendors; HITRUST is not expected at this size (incumbents claim SOC 2, not HITRUST).
    • The proposed 2025 Security Rule update (mandatory encryption, MFA, annual pen tests) is not final, with final action projected around July 2027. Build to it anyway.
  • 06

    Research: hospital identity providers & SSO

    Resolved
    • Assume Microsoft Entra ID, with Imprivata badge-tap on shared workstations. Okta is second and Ping a distant third (directional only; real share data is behind KLAS).
    • Build SAML 2.0 first, then OIDC. SCIM 2.0 is expected at enterprise scale; a single-department pilot can create accounts on first SSO login.
    • Better Auth SSO and SCIM plugins cover SAML, OIDC, per-Organization providers, domain verification and SCIM for v1, with no licence cost. Zoe owns security patching; several high-severity SSO advisories in 2026 are fixed in current versions.
    • Phones: long sliding session; the hospital's IdP policy decides re-authentication. Never log out on app switch. Badge-tap is Imprivata's job.
  • 07

    Research: Epic / paging / clinical-comms integration paths

    Resolved
    • Epic On-Call Finder is fed by a flat file, not an API. A CSV over SFTP every 5–10 minutes, imported and mapped to Epic Team IDs by the hospital's Epic team. No certification is needed. Secure Chat reads On-Call Finder, so one feed covers both. There is no FHIR or HL7 write path for on-call.
    • Paging and comms vendors build their own connectors against the scheduler: Spok: API push every 15 minutes, or CSV over SFTP.; Vocera and PerfectServe: poll a REST feed for the next 48 hours.; TigerConnect: maps schedules to roles.; Voalte: mostly links out.; Hospital IT handles SFTP, firewalls and ID mapping.
    • Cost is hospital labour and Epic's build queue, not program fees (Epic Vendor Services is about $1.9k a year; a Showroom listing needs a live customer first).
    • Day-one need (inference): keep the hospital's existing on-call lookup working. Minimum Zoe surface: a JSON on-call feed at least 48 hours ahead, with stable external IDs and call order; the same as CSV pushed over SFTP every 5–15 minutes; a publish/change webhook; an ID-mapping table and token auth; no FHIR in v1
  • 08

    Research: payroll & HCM export formats

    Resolved
    • ADP Workforce Now and Vantage, UKG, Workday and Dayforce all import time as hours or amounts per employee, per date, per pay code, validated against a pay-code table the customer configures. Zoe's current scheduled/worked/variance CSV cannot be loaded as-is.
    • Minimum v1 export: a long-format CSV with one row per employee, work date and pay code, driven by a per-Department pay-code mapping. Columns: employee_payroll_id, company_code, batch_id, period_start, period_end, work_date, pay_code, hours, units, amount, cost_center, source_ref.
    • Hospitals usually route schedule → timekeeping (often UKG) → payroll, and timekeeping calculates overtime (40-hour week or the 8/80 rule). Zoe exports classified time and leaves overtime to the hospital.
    • Physicians are FLSA-exempt (29 CFR 541.304) and are paid flat amounts: call stipends, per-shift rates, differentials. So amount and units columns are required, not just hours.
  • 09

    Research: constraint solvers for Auto-fill at scale

    Resolved
    • v1: keep the greedy Auto-fill. It already meets the hard requirements: fills only gaps, respects Locked Assignments, explains every pick, deterministic. Its weakness is period-wide fairness, because it never revisits earlier picks.
    • Future solver: CP-SAT (Google OR-Tools, Apache-2.0).; Models Zoe's Rules directly.; Fixes Locked Assignments.; Accepts the current schedule as hints.; Runs deterministically.; Can name the conflicting Rules for an unfillable gap.; It has no official Node binding, so it needs a Python sidecar behind the same Auto-fill interface.
    • Rejected for now:; highs-js (MIT, in-process): single-threaded; likely struggles at 300 staff × 3 months (inference, needs a benchmark).; Timefold Community: Java-only, and its explanation features are Enterprise-only.; Gurobi: commercial.; CBC: volunteer-maintained.
    • Keeping explanations with a solver: show Rule slack, re-solve with "why not this person?" forced (counterfactual), and name the conflicting Rules for unfilled gaps.
